# CanvasCore 0.3.2 — menu color/gap fixes + authentic preview

## Files to replace
Backend: `canvascore-admin/compiler.php`, `api.php`, `rebuild_all.php`,
`master.html`, `version.json`
Frontend: `src/components/MenuBuilder.jsx`, `src/components/GlobalSettings.jsx`
Plus: `CHANGELOG.md`
→ then `cd canvascore-frontend && npm run build`

## Bugs fixed
1. **Menu colors** (text and hover on top-level items) and **hover
   background** were not applied: a specificity conflict with the theme's global
   rules. The menu is now authoritative (it uses `!important` on its own colors)
   and the legacy menu rules have been **removed from `master.html`**: the
   colors you set always win, on both menus and submenus.
2. **Logo / buttons gap** not applied in the real menu: a `margin:0` on the list
   reset the gap's `margin-left`. Fixed.

## New
- **Authentic preview**: the Menu Builder now shows the menu generated by the
  real compiler, inside an isolated iframe. It is identical to what you will see
  on the site (hover, effects, logo, alignment), with the links made inert. It
  updates by itself while you configure.
- **Flag in Global Settings**: "Let the menu inherit the global brand
  color on hover" (default OFF). Off → the menu uses only its own colors; on
  → hover uses the global brand color. As you suggested: without the flag the
  component uses its own rules and ignores the global style.

## Important
- Replace `master.html` too: that is where the conflicting rules lived.
  (The `!important` fix works even without it, but it is cleaner this way.)
- After the update: reopen the Menu Builder and **save** again to republish the
  pages with the updated CSS; then hard refresh.
